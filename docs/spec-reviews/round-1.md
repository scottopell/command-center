**Review basis:** the first complete five-feature draft, three Allium files, eight ADRs, and acceptance journeys. The pre-review snapshot is retained in the task's working directory. This is an author-run adversarial pass, not an independent-agent review.

## Cross-feature contradictions and repairs

1. **Fresh launch versus restoration.** Shell destructive switching conflicts with framework wording that could implicitly restore a saved draft. Resolve by forbidding automatic hydration and treating saved temporary data as function-explicit only; DRQS Add always starts fresh. Bare A never recovers an old uncertain Quick creation.
2. **Escape versus hook completion.** Returning screen/focus is not allowed to await cleanup. A same-thread deadline is insufficient; mechanism experiments must prove the native host can abandon cleanup independently. Proposed narrower snapshot hook requires user approval.
3. **UI cancellation versus accepted writes.** Admission is the handler boundary after validation, not the existence of an HTTP connection. Leaving the view does not cancel, repeat, or roll back accepted work. Lost response is a client observation, not a failed database transaction.
4. **Interactive focus versus initialization ownership.** The command bar must not consume post-GO text while the loader runs. Give loading capture its own logical ownership, distinct from command editing, even if a native text control implements both.
5. **Read-only focus versus early text.** HOST's container is a valid initial focus target, but text cannot be replayed into a non-text destination. Refuse that handoff explicitly rather than guess an editable field or send it to the command bar.
6. **Generation safety versus duplicate completion.** A matching generation alone is insufficient. Resolution and focus completions must also match the expected phase and be single-use. Discard unexpected or duplicate completions rather than remounting.
7. **Formal event exposure.** Several Allium events lacked a providing surface, making the intended driving boundary unclear. Expose user Escape separately from framework-owned drain events and backend transport/handler completion events. Remove unused derived active references or expose them meaningfully.
8. **Contract type examples versus real DRQS schema.** The reference parser returns action/group, not the illustrative groupId field used in chat. New DRQS must define a consistent typed variant; do not copy mismatched example fields into production contracts.

## Hidden commitments

The accepted minimum still includes one managed local service, a local client credential, transactional persistent data, a native/web bridge, and real browser input acceptance tests. These are material but directly support the approved journeys. No current requirement justifies autonomous agents, a scheduler, durable job queue, remote multi-user service, shared live editing, generalized plugin loading, or full editor emulation.

## Complexity collapses

Already reflected in the draft: one service rather than one process per function; ordinary RPC rather than queued jobs; local transactions rather than probabilistic numbering; explicit refresh rather than subscriptions; static built-ins rather than a plugin loader; selected read-only host observations rather than toolkit rehosting. User decisions are requested before narrowing loading-time input, early submit, or unload behavior.

## Residual implementation gates

Disposable realm retention, loading-time text handoff, and native Escape responsiveness are not established by documentation or Allium syntax checks. Their Proposed ADRs need actual prototypes. The spec set must remain visibly unimplemented until those results exist.
